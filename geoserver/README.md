# GeoServer (162.245.218.6) - findings and what to change

Nothing in this folder has been applied to the live GeoServer yet. GeoServer is shared with the other portal,
so every change below touches only the `AwasVikas` workspace (store `Awas_Vikas_Parishad`, 8 layers, 8 styles).

## What was measured

| Check | Result |
|---|---|
| PostGIS, full-city plot query (172k rows) | 31 ms (index OK, stats current) |
| GeoServer -> database round trip | **250 ms** (ping) |
| Portal server / load balancer -> database | 0.2 ms |
| Portal server / load balancer -> GeoServer | 244 ms |
| Plot layout, whole city, one image | 45 s (172 batches of 1,000 rows x 250 ms = 43 s) |
| Same request, new scale-aware SLD sent per request | no real change (19 s -> 31 s at zoom 15, buildings at zoom 15 1.3 s because hidden) |

Conclusion: the time is network round trips between GeoServer and the database, not drawing and not SQL.
Styles help readability and avoid useless work at far zoom levels, but are not the main fix.

## Changes, in order of value (all need GeoServer admin access)

1. **JDBC fetch size** on store `Awas_Vikas_Parishad`: `fetch size` 1000 -> **50000**
   (Data > Stores > Awas_Vikas_Parishad > Connection parameters). Cuts 172 round trips to ~4.
   Also set `min connections` 5 (every new JDBC connection costs ~6 round trips = 1.5 s).
2. **Read-only account**: the store currently connects as `upavp_geo_dev` (full write access, password in the
   datastore.xml). Use `upavp_geo_geoserver` (read-only; exists, tested). For JNDI add a
   `jdbc/upavp_geo` Resource to `/var/lib/tomcat9/conf/Catalina/localhost/geoserver.xml` (needs a Tomcat
   reload = ~1 min blip for the other portal, so do it in a quiet window).
3. **Scale-dependent styles**: `styles/scaled/*.sld` (generated by `make_scaled_styles.py`; originals in
   `styles/original`). Plot labels only at zoom 17+, plots from zoom 15 (fill only) / 16 (outline),
   buildings from zoom 16, landuse from zoom 14, line widths by zoom band, railway ties and water outlines
   only when zoomed in. Apply per style with REST:
   `curl -u admin:*** -XPUT -H "Content-type: application/vnd.ogc.sld+xml" -d @scaled/layout.sld http://162.245.218.6:8080/geoserver/rest/workspaces/AwasVikas/styles/layout`
   then truncate that layer's tile cache (GWC > Caching defaults / `rest` truncate) and re-seed.
4. **Seed the tile cache** (GWC): zoom 12-16 over the GDA extent for the 7 dashboard layers, so no user
   ever waits for a first render.
5. **Best structural fix**: run a GeoServer for this project in the same data centre as the database
   (e.g. a small VM next to 27.100.38.132). Round trips drop from 250 ms to 0.2 ms - every layer becomes
   ~1000x cheaper on the database leg, and the two portals are fully separate (own Tomcat, own pool, own
   data directory). The portal server has only 2.9 GB free disk, so use another host for it.

## Why SLD and not "CSS"
GeoServer's CSS style extension is not installed (checked `WEB-INF/lib`), and SLD works everywhere, so
the styles are SLD with `Min/MaxScaleDenominator`.
